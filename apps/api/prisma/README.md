# Prisma

## Conventions

Every model added here must follow SDD §6.1. In short:

| Rule | Why |
|---|---|
| `String @id @db.Uuid`, generated by `UuidV7Generator` | Time-ordered keys keep B-tree inserts sequential (ADR-005) |
| `@map` / `@@map` to `snake_case` | Database convention differs from TypeScript convention on purpose |
| `@db.Timestamptz(6)` | Never `timestamp without time zone` |
| `BigInt` + explicit currency column for money | Floating-point currency errors are unrecoverable (ADR-006) |
| `deletedAt DateTime?` on user-visible entities | Soft delete; hard delete only via the DPDP erasure job |
| No `UPDATE`/`DELETE` on financial and audit tables | Corrections are reversing entries, enforced by trigger |

## Things Prisma cannot express

Several constraints this platform depends on have to be added as raw SQL inside
a generated migration. Do not skip them:

- `CHECK` constraints (e.g. `remaining_quantity >= 0`, which is what makes
  overselling a preorder impossible regardless of application bugs — SDD §14.4)
- Partial and expression indexes
- PostGIS `geography` columns and GiST indexes
- Declarative range partitioning on `audit_logs` and `outbox_events`
- Append-only triggers
- Row-level security policies

Workflow: `pnpm db:migrate --create-only`, hand-edit the SQL, then apply.

## Commands

```bash
pnpm db:generate        # regenerate the client after a schema change
pnpm db:migrate         # create and apply a migration (development)
pnpm db:migrate:deploy  # apply pending migrations (CI / production)
pnpm db:studio          # browse the database
pnpm db:format          # format schema.prisma
```

## Migration safety

Migrations are forward-only and must be backward-compatible with the currently
deployed application (expand → migrate → contract across three releases). A
rolling ECS deploy runs both versions simultaneously; a destructive migration in
the same release that stops using a column will take the old tasks down.
